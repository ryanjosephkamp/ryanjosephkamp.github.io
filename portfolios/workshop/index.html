Splashery

Splats you can play with.

An interactive Gaussian splat playground that runs entirely in the browser. Pick a toy, a real captured object or one generated from a seed, then spin it, poke it, blow on it, splash paint on it, drop it, watch it fall apart and come back, make your own, and share it as a link, an embed, a GIF or a video.

My part. I defined the project vision and toy categories, directed multi-agent development, refined interaction design through hands-on testing, and contributed selected mathematical recipes.

The building is done by coding agents. Splashery’s repository keeps its own loop graph: a worker builds a lane, the full test run and a clip review send it back until the work is right, and anything the public already sees waits behind a human gate. That gate is where I sit.

Play with it Source The Tinkerer’s Manual

One kit, shared by area

  • Donuttorus, param, cylinder
  • Saturnsphere, disc
  • Ice creamcone, sphere
  • Torus knottube

Splashery’s toy kit builds a toy from shapes and shares the splat budget between them by surface area, so the whole toy has an even density. The four toys on sheet 1 are built from seven of its shapes, and shared out the same way.

No build step

Static files and ES modules only. No bundler, no framework, no server, no API keys. Rendering is the PlayCanvas engine, vendored, on WebGPU when the browser has it and WebGL2 otherwise.

Every splat, every frame

Poke, wind, dissolve, drop, magnet, twist, slice and paint all run on the GPU for every splat, every frame. The CPU only sets a few uniforms. Effects stack.

grooph

Loop graphs for coding agents.

Visual loop graphs for coding-agent workflows. You, or an agent working with you, draw who builds, who checks, where a person decides and when the work stops. grooph checks that every loop names a stop and every bar names what a critic can inspect, then compiles the graph into a prompt package for a separate coding-agent harness. It runs no agent and calls no model, and graphs stay on your device.

My part. I implemented a multi-agent pipeline and refined a visual tool for expressing builder/checker roles, human decision points and stopping conditions in coding-agent workflows.

Limits, from its own README

“No round cap or budget is on record as firing, so it is not shown that one holds a run that would otherwise go on. In a paired comparison on four small tasks the package showed no quality advantage over a prompt derived from it.”

The five graphs on sheet 1

Each is one of grooph’s built-in templates with its blanks filled in for the drawing, saved here as a graph document. grooph validate --for-export finds no errors in any of them; the two warnings are printed below as it gave them. The round cap in the review gate is one a visitor can make fire: keep rejecting the drawing, and the run halts at four rounds.

The drawer

Other things I have built, filed flat.

reword_nerd

A local-first browser workbench that turns a reviewed document, or a set of images, into a portable workbook of rewriting prompts. Everything stays reviewable in the browser, the download is a separate, explicit step, and the application contacts no model provider itself.

OpenWrite-upSource

Its Manual workflow runs four stages, each response feeding the next prompt. Change a response upstream and the prompts you edited downstream are kept and marked stale until you reapply or reset them. Tap a stage to change its response.

Link Meteor

A Chrome extension that collects links with their anchor text and URL in separate fields, for reviewing sources and exporting a research collection. No account, ads, telemetry or backend.
